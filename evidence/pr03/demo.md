# PR03 — patrol: демонстрация и наблюдения

Нода `patrol` подписывается на `/turtle1/pose`, хранит последнее сообщение,
а таймер с периодом 0,1 с публикует `geometry_msgs/msg/Twist` в относительный
`cmd_vel`. До получения позы функция `command_for_pose` возвращает нулевой
Twist; для полученной позы задаёт `linear.x=0.5` и `angular.z=0.3`.

## Запуск с исправленной связью

В ROS 2 Lyrical активировать среду и overlay нужно в каждом терминале. Домен
должен совпадать у turtlesim и patrol. Терминал A запускает turtlesim через
`turtle_bringup`; в терминале B:

```bash
ros2 run patrol patrol --ros-args -r cmd_vel:=/turtle1/cmd_vel
```

В терминале C выполнены проверки:

```bash
ros2 node list --no-daemon --spin-time 2
ros2 topic info /turtle1/pose --verbose
ros2 topic info /turtle1/cmd_vel --verbose
ros2 topic hz /turtle1/cmd_vel
```

В графе обнаружены `/patrol` и `/turtlesim`. Тип Pose у издателя turtlesim и
подписчика patrol совпадает: `turtlesim_msgs/msg/Pose`. У
`/turtle1/cmd_vel` обнаружены издатель patrol и подписчик turtlesim.
`ros2 topic hz` показал среднюю частоту около **10.000–10.001 Hz**; в выводе
видны интервалы 0.099–0.101 с и окна до 309 сообщений (более 10 секунд).

## Дефект имени и исправление

Без remap нода публикует в относительный `cmd_vel`; при namespace `/` полное
имя — `/cmd_vel`:

```bash
ros2 run patrol patrol
ros2 topic info /cmd_vel --verbose
ros2 topic info /turtle1/cmd_vel --verbose
ros2 topic hz /cmd_vel
```

Для `/cmd_vel` CLI показал издателя patrol и **0 подписчиков**. Для
`/turtle1/cmd_vel` было **0 издателей** и подписчик turtlesim. Несмотря на
одинаковый тип `geometry_msgs/msg/Twist`, это разные полные имена топиков,
поэтому команда от patrol не соединялась с turtlesim. Частота ошибочного
издателя также была около **10.000 Hz** (окна свыше 200 сообщений): частота и
тип не исправляют несовпадение имени.

После остановки процесса и повторного запуска с единственным изменением —
remap `cmd_vel:=/turtle1/cmd_vel` — CLI показал один издатель patrol и одного
подписчика turtlesim на `/turtle1/cmd_vel`. Измеренная частота составила
около **10.000 Hz**, интервалы 0.099–0.101 с.

Повторная проверка типа позы показала `turtlesim_msgs/msg/Pose` у обоих
концов. При отладке также была исправлена ошибка импорта: `Pose` берётся из
`turtlesim_msgs`, а `Twist` — из `geometry_msgs`.

## Жизненный цикл и остановка

- `rclpy.init` подготавливает ROS-контекст.
- Конструктор `Patrol` создаёт ноду, подписку, издатель и таймер.
- Callback подписки сохраняет последнее сообщение Pose.
- Callback таймера выбирает команду и публикует Twist.
- `rclpy.spin(node)` обрабатывает входящие сообщения и срабатывания таймера.
- `Ctrl+C` вызывает обработку `KeyboardInterrupt`, после чего нода уничтожается
  и ROS-контекст завершается.

Остановка процесса прекращает поток Twist, но сама по себе не является
мгновенной командой торможения. После `Ctrl+C` следует наблюдать turtlesim и
дождаться остановки черепахи; при повторном запуске убедиться, что старый
экземпляр patrol завершён.

В отчёт вошли фактические выводы CLI, переданные студентом. Окно turtlesim и
физическое движение не проверялись этим CI; функциональная демонстрация
поведения выполняется локально.
